# 001 — M0 repository foundation

Status: done
Milestone: M0
ADRs: 0002, 0010, 0011, 0014, 0015

## Goal

A new repository, protected on GitHub, where the agreed checks run locally and in CI and are proven to fail on
deliberate violations — before any product code exists.

## Scope rules

- Create only what M0 needs: the Django project (`backend/config/`), the directories its settings reference,
  tooling configuration, Makefile, Compose, Docker `dev` target and CI.
- Do **not** create module packages (`core`, `media`, `catalog`, `content`, `storefront`, `backoffice`) or empty
  `domain.py`, `application.py`, `repositories.py`, `api.py` files. Each module is created, with its
  import-linter contracts, by the milestone that first needs it (target layout: `docs/architecture.md` §11).
- No product domain code. Real repository contracts are validated in M1, persistence in M2.
- Negative checks use temporary fixtures that are removed before merge. Secrets used in tests are synthetic, never
  real credentials.

## Ordered checklist

### A. Decisions (human)

1. Confirm the pre-M0 decisions at the end of this spec.

### B. Local repository (human)

2. Create a new, empty project directory named after the repository.
3. Extract `ciclopinhalend-docs.zip` and move the **contents** of its top-level `ciclopinhalend-docs/` folder into
   the project root (so `README.md`, `AGENTS.md`, `CLAUDE.md` and `docs/` sit at the root).
4. Initialise Git with `main` as the default branch (`git init -b main`).
5. Check that only documentation is present (`git status`), then make the initial commit, e.g.
   `docs: add approved documentation baseline`.

### C. GitHub repository (human)

6. Create an empty **public GitHub Free** repository per approved E4 — no README, licence or
   `.gitignore` generated by GitHub.
7. Add it as `origin` and push `main`.
8. Settings: merge method squash only.
9. `main` ruleset: PR required, linear history, no force-push, no deletion; one approving review if E4b = (a).
   Required status checks are added in step 22, after they have run once.
10. `v*` tag ruleset: creation restricted to Repository admin; update and deletion blocked.
11. Enable Dependabot alerts and version updates, GitHub secret scanning and push protection (public repository).
12. Agent access per E4b:
    - (a) Create the agent machine account with 2FA, add it as a collaborator with write access, create its token
      for Claude Code; check which GitHub identity Codex uses and give it no admin rights.
    - (b) Record the shared-credentials decision and residual risk in an ADR before step 13.

### D. M0 branch (human)

13. Create `chore/m0-foundation` from `main` and push it; hand the branch and this spec to the implementing agent.

### E. Implementation (implementing agent, on `chore/m0-foundation`)

14. `pyproject.toml` (Python 3.13, Django 5.2 runtime deps, `dev` group), `uv.lock`, `.gitignore`, `.dockerignore`,
    `.env.example` with variable names only.
15. Django project in `backend/config/` with settings `base`, `dev`, `test`, `prod` and `env.py`; `frontend/templates/`
    and `frontend/static/` referenced by settings.
16. `compose.yaml` with PostgreSQL 17 (and the `app` service); `Dockerfile` with the `dev` target.
17. Tooling configuration: Ruff, mypy (scope and flags from `docs/engineering.md` §1), import-linter, pytest with
    markers, gitleaks, relation allowlist test (empty allowlist).
18. One infrastructure test proving pytest-django reaches PostgreSQL. No product tests.
19. `Makefile` targets `setup`, `up`, `check`, `test-fast`, `test` (`e2e` is added in M6).
20. CI workflow with jobs `quality`, `test`, `migrations` (destructive-operation check added in M2), `security`,
    `secrets`; Actions pinned to commit SHAs; Dependabot configuration for uv, Actions and Docker.

### F. Verification and merge

21. Prove each negative check (section "Negative checks") on a throwaway branch or local run, record the evidence
    (CI run links or command output) in the M0 PR description, then delete the fixtures. The fixtures are never
    merged.
22. After the first CI run on the M0 PR, add `quality`, `test`, `migrations`, `security`, `secrets` as required
    status checks on the `main` ruleset.
23. If E4b = (a), verify with the agent identity that it can push a branch and open a PR, but cannot push to
    `main` or create a `v*` tag.
24. Review by the other agent; human acceptance; squash merge.

## Acceptance criteria

- [x] Fresh clone with only Docker and uv: `make setup && make up && make test` passes.
- [x] `make check` runs Ruff format/lint, `uv lock --check`, mypy, import-linter and gitleaks.
- [x] CI installs with `uv sync --locked`; `manage.py check --deploy` passes with prod settings and dummy values.
      (Run as `make deploy-check`: Django's deployment checks pass with the four deferred warnings listed in
      `deploy-warnings-deferred.txt`, printed and not suppressed; `docs/engineering.md` §7.)
- [x] Every negative check in the table failed as expected; evidence is linked in the PR; no fixture remains in
      the merged tree.
- [x] Required status checks are active on `main`; the `v*` tag ruleset is active.
- n/a If E4b = (a): the agent identity cannot push to `main` or create a `v*` tag. E4b = (b), see ADR-0015.
- [x] No module packages, domain code or empty layer files exist yet.
- [x] No real secrets anywhere; `.env` is ignored by Git and Docker.

If import-linter cannot run without at least one contract while no modules exist, the implementing agent keeps
the smallest real contract possible for `backend.config` and states it in the PR.

### Not verified by an agent

- The negative checks were run locally, not in CI; CI shows the positive run only.
- Required approvals, admin-only tag creation, squash-only merge, Dependabot alerts, secret scanning and push protection
